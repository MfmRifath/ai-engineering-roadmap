# R2 — Working with Text Data

> **Thesis:** Getting from a text file to a batch of tensors involves five distinct decisions,
> and each one shapes what the model can learn.

## Why this chapter matters

This is the input pipeline, built by hand: tokenizer → IDs → sliding-window dataset → embeddings
→ positional encodings. You will write every piece. It is the concrete version of
[A2](../../02-hands-on-llms-alammar/notes/ch02.md) and it is where "the model never sees text"
stops being a slogan.

## Core concepts

### Building a tokenizer from nothing

Raschka's escalation is pedagogically excellent — each version fails, and the failure motivates
the next.

**V1: split on whitespace and punctuation.** Build a vocabulary from the corpus, map strings to
IDs. Works until a word appears that was not in the training text — then `KeyError`.

**V2: add special tokens.** `<|unk|>` for unknown words, `<|endoftext|>` to separate documents.
Now it does not crash, but every unknown word collapses to the same meaningless token — all
information about it is gone.

**V3: byte pair encoding.** No unknown tokens are possible, because any word decomposes into
subwords, and any subword decomposes into characters. The `KeyError` cannot happen by
construction.

The BPE training loop is short enough to hold in your head:

```
vocab = all individual characters
while len(vocab) < target_size:
    pair = most frequent adjacent pair in corpus
    merge pair into a new token
    add it to vocab
```

Raschka uses `tiktoken` (GPT-2's actual BPE) for the book, and Appendix bonus material walks
through implementing BPE from scratch. **Do the from-scratch version** — it is a couple of hours
and it permanently demystifies tokenization.

Sanity check worth running: encode `"Akwirw ier"` (Raschka's exercise 2.1) — a nonsense string —
and watch it decompose into subword fragments and reconstruct exactly.

### Sliding-window sampling

For next-token prediction, the target is the input shifted by one:

```
text:    "LLMs learn to predict the next"
input:   [LLMs, learn, to, predict, the]
target:  [learn, to, predict, the, next]
```

Every position is a training example simultaneously — position 0 predicts position 1, position 1
predicts position 2, and so on, all in one forward pass. That is why the causal mask matters so
much ([A3](../../02-hands-on-llms-alammar/notes/ch03.md)): without it, position 2 could look at
position 3, which is literally its answer.

**Stride** controls the overlap between consecutive training windows:

| Stride | Effect |
|---|---|
| `stride = max_length` | No overlap. Every token seen once per epoch. Efficient. |
| `stride < max_length` | Overlap. More examples, more compute, risk of memorization. |
| `stride = 1` | Maximum overlap. Wasteful. |

Raschka's default is `stride = max_length` — no overlap, no duplicated data.

### Token embeddings

An `nn.Embedding(vocab_size, output_dim)` layer is a **lookup table**: a
`(vocab_size, output_dim)` weight matrix where `embedding(i)` returns row *i*.

Raschka makes the point explicitly by comparing it against one-hot encoding followed by a matmul
— they are mathematically identical, but the lookup is far more efficient. That equivalence is
worth seeing once.

For GPT-2 small: `nn.Embedding(50257, 768)` = **38.6M parameters** in the embedding table alone,
about 31% of the model's 124M. Embeddings are not a small detail.

The weights are **random at initialization** and learned by gradient descent like everything else
([G13](../../01-hands-on-ml-geron/notes/ch13.md)).

### Positional embeddings

Self-attention is permutation-invariant ([G16](../../01-hands-on-ml-geron/notes/ch16.md)), so
position must be injected. Raschka uses GPT-2's approach: a second, **learned** embedding table
of shape `(context_length, output_dim)`, indexed by position and **added** to the token
embedding.

```python
input_embeddings = token_embeddings + pos_embeddings
```

Simple addition into the same vector. The model learns to disentangle the two signals.

`[dated]` Modern models use **RoPE** instead ([A3](../../02-hands-on-llms-alammar/notes/ch03.md)),
which rotates Q and K rather than adding to the input and generalizes better to longer contexts.
Learned absolute positions have a hard limit: you cannot exceed `context_length`, because there is
no row in the table for position 1025.

## Key code

```python
import torch
from torch.utils.data import Dataset, DataLoader
import tiktoken

class GPTDatasetV1(Dataset):
    """Sliding windows over a tokenized corpus. Target = input shifted by one."""
    def __init__(self, txt, tokenizer, max_length, stride):
        self.input_ids, self.target_ids = [], []
        token_ids = tokenizer.encode(txt, allowed_special={"<|endoftext|>"})
        for i in range(0, len(token_ids) - max_length, stride):
            self.input_ids.append(torch.tensor(token_ids[i:i + max_length]))
            self.target_ids.append(torch.tensor(token_ids[i + 1:i + max_length + 1]))

    def __len__(self):
        return len(self.input_ids)

    def __getitem__(self, idx):
        return self.input_ids[idx], self.target_ids[idx]


def create_dataloader_v1(txt, batch_size=4, max_length=256, stride=128,
                         shuffle=True, drop_last=True):
    tokenizer = tiktoken.get_encoding("gpt2")
    dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)
    return DataLoader(dataset, batch_size=batch_size, shuffle=shuffle,
                      drop_last=drop_last, num_workers=0)


# Embeddings: token identity + position, summed
vocab_size, output_dim, context_length = 50257, 768, 1024
tok_emb = torch.nn.Embedding(vocab_size, output_dim)      # 38.6M params
pos_emb = torch.nn.Embedding(context_length, output_dim)

inputs, targets = next(iter(create_dataloader_v1(raw_text)))
x = tok_emb(inputs) + pos_emb(torch.arange(inputs.shape[1]))
print(x.shape)     # (batch, seq_len, 768)
```

## Gotchas

- **Off-by-one in the target shift.** `targets = token_ids[i+1 : i+max_length+1]`. Get this wrong
  and the model learns to copy its input, which produces a suspiciously low loss.
- **Forgetting `drop_last=True`.** A final short batch gives inconsistent shapes.
- **`stride < max_length` without meaning to.** You duplicate training data and inflate epoch
  counts.
- **Adding embeddings of mismatched shape.** `pos_emb` must be indexed by
  `torch.arange(seq_len)`, and broadcasting will silently do the wrong thing if you get the
  dimensions wrong.
- **Exceeding `context_length` with learned positional embeddings.** There is no row for position
  1025. Hard limit.
- **Mixing tokenizers.** Encode and decode with the same one, always.
- **Forgetting `allowed_special`.** `tiktoken` raises on `<|endoftext|>` unless you permit it.

## Flashcards

<!-- card -->
Q: Why does byte pair encoding eliminate unknown tokens?
A: Any word decomposes into subwords already in the vocabulary, and in the limit into individual characters or bytes. The `KeyError` is impossible by construction, so no `<unk>` token is needed.
<!-- /card -->

<!-- card -->
Q: How is the target constructed for next-token prediction training?
A: The target is the input shifted right by one: `targets = tokens[i+1 : i+max_length+1]`. Every position becomes a training example in a single forward pass — which is exactly why causal masking is required.
<!-- /card -->

<!-- card -->
Q: What does the `stride` parameter control in the sliding-window dataset?
A: The overlap between consecutive training windows. `stride = max_length` means no overlap and each token is seen once per epoch; smaller stride creates more (partially duplicated) examples and more compute.
<!-- /card -->

<!-- card -->
Q: What is `nn.Embedding` mechanically, and how big is GPT-2 small's?
A: A trainable lookup table — a (vocab_size, dim) weight matrix where `embedding(i)` returns row i, mathematically identical to one-hot × matrix but far more efficient. GPT-2 small: 50257 × 768 = 38.6M parameters, about 31% of the model.
<!-- /card -->

<!-- card -->
Q: How does GPT-2 encode position, and what is the limitation?
A: A second learned embedding table of shape (context_length, dim), indexed by position and *added* to the token embedding. The limitation is a hard context ceiling — there is no row for a position beyond context_length.
<!-- /card -->
