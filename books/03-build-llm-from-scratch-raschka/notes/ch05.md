# R5 — Pretraining on Unlabeled Data

> **Thesis:** Training an LLM is cross-entropy loss and a standard training loop — the same loop
> from [G12](../../01-hands-on-ml-geron/notes/ch12.md), applied to a 50,257-way classification at
> every position.

## Why this chapter matters

Two payoffs. First, the model starts working: gibberish becomes recognizable English. Second, and
better, you **load OpenAI's released GPT-2 weights into your own architecture** — and it
generates properly. That is unambiguous proof your implementation is correct, and it is the most
satisfying moment in the book.

## Core concepts

### The loss

Next-token prediction is multiclass classification over the vocabulary, so the loss is
**cross-entropy** ([G4](../../01-hands-on-ml-geron/notes/ch04.md)) — averaged over every position
in every sequence in the batch.

Raschka builds it up manually before using the built-in, which is worth following:

1. Logits → softmax → probabilities
2. Take the probability assigned to the *correct* token
3. Take the log
4. Average over all positions
5. Negate

```python
# The manual version, for understanding
probas = torch.softmax(logits, dim=-1)
target_probas = probas[batch_idx, token_idx, targets]
loss = -torch.log(target_probas).mean()

# The version you actually use: numerically stable and fused
loss = torch.nn.functional.cross_entropy(
    logits.flatten(0, 1),    # (batch*seq, vocab)
    targets.flatten(),       # (batch*seq,)
)
```

**Use the built-in.** It fuses log-softmax with the negative log-likelihood using the log-sum-exp
trick, which is numerically stable where the naive composition overflows — exactly the point
[G12](../../01-hands-on-ml-geron/notes/ch12.md) makes.

Note `cross_entropy` expects **raw logits**, not probabilities. Passing softmax output is a
classic silent bug: it trains, badly.

### Perplexity

$$\text{perplexity} = \exp(\text{cross-entropy loss})$$

Interpretable as **the effective number of tokens the model is choosing among**. Perplexity 1
means certainty; perplexity 50,257 means uniform guessing over the whole vocabulary.

A loss of 10.9 (an untrained model — note that ln(50257) ≈ 10.8) corresponds to perplexity
~50,000: the model has learned nothing. Loss 3.0 → perplexity ~20: it has narrowed to about
twenty plausible options.

Perplexity is the standard LLM training metric, and it reappears as an evaluation metric in
[H3](../../04-ai-engineering-huyen/notes/ch03.md), where Huyen also explains its limits — it
measures fit to a distribution, not usefulness.

### The training loop

Recognizably the loop from [G12](../../01-hands-on-ml-geron/notes/ch12.md):

```python
for epoch in range(num_epochs):
    model.train()
    for input_batch, target_batch in train_loader:
        optimizer.zero_grad()                     # PyTorch accumulates gradients
        loss = calc_loss_batch(input_batch, target_batch, model, device)
        loss.backward()
        optimizer.step()
```

Four lines. Everything else — evaluation, logging, checkpointing, sampling — is instrumentation.

**AdamW**, not Adam. Decoupled weight decay ([G11](../../01-hands-on-ml-geron/notes/ch11.md)),
the standard for transformers.

Raschka trains on *The Verdict*, a short story of ~20,000 tokens. The model **overfits heavily** —
validation loss rises while training loss falls, and it eventually reproduces passages verbatim.
He is explicit that this is expected with so little data, and it is a good visible demonstration
of [G4](../../01-hands-on-ml-geron/notes/ch04.md)'s overfitting on a model you built yourself.

### Sampling: from greedy to controlled

Greedy decoding (argmax) is deterministic and repetitive. Two knobs fix it —
implemented here rather than merely described ([A6](../../02-hands-on-llms-alammar/notes/ch06.md)):

**Temperature** — divide logits before softmax:

```python
logits = logits / temperature
probs = torch.softmax(logits, dim=-1)
next_token = torch.multinomial(probs, num_samples=1)   # sample, don't argmax
```

Raschka's demonstration of temperature's effect on the probability distribution — a bar chart at
T = 0.1, 1, 5 — is the clearest illustration of what the parameter does. T → 0 approaches argmax;
T → ∞ approaches uniform.

**Top-k** — keep only the *k* highest logits, set the rest to −∞, then softmax:

```python
top_logits, _ = torch.topk(logits, top_k)
logits = torch.where(logits < top_logits[:, -1], torch.tensor(float("-inf")), logits)
```

The −∞-before-softmax trick again, exactly as with causal masking
([R3](ch03.md)). Once you notice the pattern you see it everywhere.

Combined, temperature and top-k give diverse but not incoherent output. `[dated]` **top-p**
(nucleus) is generally preferred now for the reason in
[A6](../../02-hands-on-llms-alammar/notes/ch06.md) — it adapts to the distribution's shape.

### Loading OpenAI's weights

The chapter's climax. Download GPT-2's released weights and map them into your model's parameters.

What makes it non-trivial and instructive:

- **Naming differs.** OpenAI's checkpoint uses TensorFlow names; you map them to yours by hand.
- **QKV are fused.** OpenAI stores a single combined QKV matrix; you split it into three.
- **Transposes.** TensorFlow's convention is transposed relative to PyTorch's `nn.Linear`.
- **Shape assertions matter.** Raschka's `assign()` helper checks shapes on every assignment. A
  silent shape mismatch produces a model that runs and generates nonsense, which is a miserable
  bug to chase.

Then it generates coherent text. **Your architecture, OpenAI's weights.** If it works, chapter 3
and chapter 4 are provably correct.

### Saving and loading

```python
torch.save({
    "model_state_dict": model.state_dict(),
    "optimizer_state_dict": optimizer.state_dict(),   # needed to resume properly
}, "model_and_optimizer.pth")
```

Save the optimizer state too. AdamW's moment estimates matter; resuming without them is a
noticeably worse restart.

## Key code

```python
def train_model_simple(model, train_loader, val_loader, optimizer, device,
                       num_epochs, eval_freq, eval_iter, start_context, tokenizer):
    train_losses, val_losses, tokens_seen = [], [], []
    global_step, seen = -1, 0

    for epoch in range(num_epochs):
        model.train()
        for input_batch, target_batch in train_loader:
            optimizer.zero_grad()
            loss = calc_loss_batch(input_batch, target_batch, model, device)
            loss.backward()
            optimizer.step()

            seen += input_batch.numel()
            global_step += 1

            if global_step % eval_freq == 0:
                tr, va = evaluate_model(model, train_loader, val_loader, device, eval_iter)
                train_losses.append(tr); val_losses.append(va); tokens_seen.append(seen)
                print(f"Ep {epoch+1} (step {global_step:06d}): "
                      f"train {tr:.3f}, val {va:.3f}, ppl {torch.exp(torch.tensor(va)):.1f}")

        generate_and_print_sample(model, tokenizer, device, start_context)
    return train_losses, val_losses, tokens_seen
```

## Gotchas

- **Forgetting `optimizer.zero_grad()`.** PyTorch accumulates gradients across backward calls. Omit
  it and gradients from every previous batch pile up — training diverges in a confusing way.
- **Passing probabilities to `cross_entropy`.** It expects raw logits and applies log-softmax
  internally. Passing softmax output trains badly without erroring.
- **Wrong flatten shapes.** `logits.flatten(0, 1)` and `targets.flatten()`. Get it wrong and you
  compute loss against the wrong targets.
- **Not calling `model.eval()` / `model.train()`.** Dropout stays on during evaluation, so your
  validation loss is noisy and pessimistic.
- **Missing `torch.no_grad()` during evaluation.** Builds a graph you never use — wasted memory,
  potential OOM.
- **Temperature applied to probabilities.** It divides *logits*.
- **Expecting good text from 20k tokens.** It will overfit and memorize. That is the demonstration.
- **Silent shape mismatch when loading weights.** Assert every shape.

## Flashcards

<!-- card -->
Q: What loss does LLM pretraining use, and why?
A: Cross-entropy, averaged over every position. Next-token prediction is multiclass classification over the vocabulary, so it is the same loss as any softmax classifier — just with K ≈ 50,000 classes at every position.
<!-- /card -->

<!-- card -->
Q: What is perplexity and how do you interpret it?
A: exp(cross-entropy loss) — the effective number of tokens the model is choosing among. Perplexity 1 is certainty; ~50,257 is uniform guessing over the whole vocabulary. Loss 3.0 ≈ perplexity 20, meaning about twenty plausible options.
<!-- /card -->

<!-- card -->
Q: Why must you call `optimizer.zero_grad()` each step?
A: PyTorch *accumulates* gradients across `backward()` calls rather than replacing them. Without zeroing, each step's update includes every previous batch's gradients and training diverges.
<!-- /card -->

<!-- card -->
Q: Why pass raw logits to `cross_entropy` rather than probabilities?
A: It applies log-softmax internally using the numerically-stable log-sum-exp trick. Passing softmax output applies the operation twice — it trains, badly, and raises no error.
<!-- /card -->

<!-- card -->
Q: How is top-k sampling implemented?
A: Keep the k highest logits, set all others to −∞, then softmax and sample. The −∞-before-softmax pattern is the same trick used for causal masking.
<!-- /card -->

<!-- card -->
Q: Why does loading OpenAI's GPT-2 weights into your own model matter?
A: If your architecture generates coherent text with their weights, your implementations of attention, the transformer block, and the full model are provably correct. It converts "I think I built it right" into proof.
<!-- /card -->

<!-- card -->
Q: What makes loading those weights non-trivial?
A: Different naming conventions (TensorFlow vs yours), a fused QKV matrix that must be split into three, and transposed weight conventions. Assert shapes on every assignment — a silent mismatch yields a model that runs and produces nonsense.
