# R6 — Fine-tuning for Classification

> **Thesis:** Swap the 50,257-way output head for a 2-way one, freeze most of the model, train
> briefly — and a text generator becomes a classifier.

## Why this chapter matters

Your first fine-tune, done by hand. It makes [G11](../../01-hands-on-ml-geron/notes/ch11.md)'s
transfer learning concrete on a model you built, and it surfaces the two design decisions that
matter in every fine-tune: **which layers to train**, and **which position to read**.

Compare it against [A4](../../02-hands-on-llms-alammar/notes/ch04.md) — frozen embeddings plus
logistic regression achieves something similar with far less machinery. Knowing both means
knowing when the heavier approach earns its cost.

## Core concepts

### The task and the data

SMS spam classification. Raschka is careful about the data preparation, and the care is the
lesson:

- **Balance the classes** by downsampling the majority. The raw dataset is heavily skewed toward
  ham, and an imbalanced set gives you a classifier that predicts "ham" and scores well
  ([G3](../../01-hands-on-ml-geron/notes/ch03.md)).
- **Split 70/10/20** train/validation/test.
- **Pad to the longest sequence** in the dataset with the `<|endoftext|>` token (ID 50256), and
  truncate anything longer than the context window.

### Changing the output head

```python
model.out_head = torch.nn.Linear(in_features=BASE_CONFIG["emb_dim"], out_features=2)
```

One line replaces the 768 → 50257 language modeling head with 768 → 2. Everything below it —
embeddings, twelve transformer blocks — is unchanged and already understands English.

That is transfer learning in a sentence: **keep the representation, replace the readout.**

### Which layers to train — the ablation that teaches

Raschka does the experiment rather than asserting a rule:

| Trainable | Result |
|---|---|
| Output head only | Works, but leaves accuracy on the table |
| Head + **final block** + final LayerNorm | **Best value** — near-full quality, small fraction of the cost |
| Everything | Marginally better, much slower, more overfitting risk |

The middle row is the practical answer, and the reason is the same as
[G14](../../01-hands-on-ml-geron/notes/ch14.md): lower layers hold general language features that
transfer; upper layers are task-specific and benefit from adaptation.

```python
for param in model.parameters():
    param.requires_grad = False              # freeze everything
for param in model.trf_blocks[-1].parameters():
    param.requires_grad = True               # unfreeze the last block
for param in model.final_norm.parameters():
    param.requires_grad = True
# (the new out_head is trainable by default)
```

### Which token to classify — the subtle and important bit

The model produces a vector at *every* position. Which one carries the classification?

**The last token.** And the reason is causal attention
([R3](ch03.md)): with a causal mask, only the final position has attended to the entire sequence.
Position 0 has seen only itself.

```python
logits = model(input_batch)[:, -1, :]     # last position only
```

This is a genuine architectural difference from BERT, which uses `[CLS]` at position 0 — it can,
because its attention is bidirectional so position 0 sees everything. **The architecture
determines where the summary lives.** Getting this right requires understanding the mask, which
is why chapter 3 mattered.

### Training

The loop is [R5](ch05.md)'s with two changes: the loss compares against class labels rather than
next tokens, and you track accuracy alongside loss.

Settings that work: AdamW at 5e-5, 5 epochs, batch size 8. It trains in minutes on a laptop and
reaches ~96–97% test accuracy.

Note the learning rate — 5e-5, not 1e-3. Same reasoning as
[A11](../../02-hands-on-llms-alammar/notes/ch11.md): the pretrained weights are good, and large
updates destroy them.

## Key code

```python
# 1. Load pretrained weights (from chapter 5)
model = GPTModel(BASE_CONFIG)
load_weights_into_gpt(model, params)

# 2. Freeze everything, then selectively unfreeze
for param in model.parameters():
    param.requires_grad = False

# 3. Replace the head — 50257 classes becomes 2
model.out_head = torch.nn.Linear(BASE_CONFIG["emb_dim"], num_classes)

# 4. Unfreeze the final block and final norm — the best-value configuration
for param in model.trf_blocks[-1].parameters():
    param.requires_grad = True
for param in model.final_norm.parameters():
    param.requires_grad = True


def calc_loss_batch(input_batch, target_batch, model, device):
    input_batch, target_batch = input_batch.to(device), target_batch.to(device)
    logits = model(input_batch)[:, -1, :]     # LAST token: only it has seen everything
    return torch.nn.functional.cross_entropy(logits, target_batch)
```

Yours: [`src/aieng/finetune/`](../../../src/aieng/finetune/).

## Gotchas

- **Using the first token instead of the last.** With causal attention, position 0 has seen only
  itself. This is the classic error for someone coming from BERT, and it produces a model that
  trains to mediocrity rather than failing loudly.
- **Forgetting to freeze before replacing the head.** The new head is trainable by default; the
  rest must be explicitly frozen or you accidentally full-fine-tune.
- **Learning rate too high.** 5e-5, not 1e-3.
- **Not balancing classes.** Your classifier predicts the majority and your accuracy looks fine.
- **Inconsistent padding.** All sequences in a batch must be the same length; pad with 50256.
- **Truncating without noticing.** Sequences longer than `context_length` lose their tail —
  which, since you classify on the last token, is exactly the part you need.
- **Forgetting `model.eval()`** for evaluation.

## Flashcards

<!-- card -->
Q: When fine-tuning a GPT for classification, which token's output do you use, and why?
A: The **last** token. With causal attention, only the final position has attended to the entire sequence — position 0 has seen only itself. BERT can use `[CLS]` at position 0 because its attention is bidirectional.
<!-- /card -->

<!-- card -->
Q: Which layers give the best quality-per-cost when fine-tuning for classification?
A: The new output head, the final transformer block, and the final LayerNorm. Lower layers hold general language features that transfer; upper layers are task-specific and benefit most from adaptation.
<!-- /card -->

<!-- card -->
Q: What single change converts a GPT language model into a classifier?
A: Replace the output head: `nn.Linear(emb_dim, vocab_size)` becomes `nn.Linear(emb_dim, num_classes)`. Everything below already understands language — you keep the representation and replace the readout.
<!-- /card -->

<!-- card -->
Q: Why balance the classes before fine-tuning a classifier?
A: An imbalanced training set produces a model that predicts the majority class and still scores high accuracy — the trap from Géron ch3. Downsampling the majority makes the metric meaningful.
<!-- /card -->

<!-- card -->
Q: Why is 5e-5 the right order of magnitude for fine-tuning, when pretraining uses larger rates?
A: The pretrained weights already encode a great deal; large updates overwrite that knowledge (catastrophic forgetting). Fine-tuning nudges rather than reshapes.
<!-- /card -->
