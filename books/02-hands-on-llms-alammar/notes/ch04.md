# A4 — Text Classification

> **Thesis:** There are four ways to classify text with modern models, they differ by three
> orders of magnitude in cost, and the cheapest one is right far more often than people assume.

## Why this chapter matters

Classification is the most common real LLM task in production — routing, moderation, intent
detection, triage — and it is where engineers most reliably over-engineer. This chapter lays out
the ladder of options so you can start at the bottom instead of the top.

It also connects directly back to [G3](../../01-hands-on-ml-geron/notes/ch03.md): the metrics are
identical. Only the feature extraction changed.

## Core concepts

### The four approaches

| # | Approach | Labeled data needed | Cost | When |
|---|---|---|---|---|
| 1 | **Task-specific model** | None (already fine-tuned) | Tiny | A model for your exact task exists |
| 2 | **Embeddings + classifier** | Some (100s–1000s) | Small | **The usual best answer** |
| 3 | **Zero-shot with embeddings** | **None** | Small | No labels at all |
| 4 | **Generative model + prompt** | None | Large | Nuanced or evolving labels |

Alammar's framing is the valuable part: this is a **ladder**, and you climb it only when the rung
below fails. Most teams start at 4 because it is the most exciting, then discover it costs 100×
more and is slower and less consistent than option 2.

### 1. Task-specific models

Someone has already fine-tuned a model for sentiment, toxicity, language ID, NER. Hugging Face
has thousands. Load and run.

```python
from transformers import pipeline
clf = pipeline("text-classification",
               model="cardiffnlp/twitter-roberta-base-sentiment-latest")
clf("This roadmap is excellent.")
```

Constraint: the model's label set must match yours. "Positive/negative/neutral" rarely maps onto
your product's actual categories.

### 2. Embeddings + a classifier — the workhorse

Two separable steps:

1. Embed each text with a sentence-embedding model — **frozen**, no training.
2. Train a small classifier (logistic regression!) on those vectors.

This is [G4](../../01-hands-on-ml-geron/notes/ch04.md)'s logistic regression, with embeddings as
features. And it is excellent:

- Trains in **seconds** on a CPU
- Needs only hundreds of examples
- Inference is one embedding call plus a dot product
- Fully interpretable, fully deterministic, trivially versioned
- Gets you a **real precision/recall curve** and a tunable threshold

> **This should be your default.** It is a strong baseline that frequently wins outright, and if
> it is not good enough you have a measured number to beat. Skipping it means you never learn
> whether the expensive approach was worth it.

### 3. Zero-shot classification with embeddings

A neat trick when you have *no* labels: embed the label *descriptions* as if they were documents,
then assign each input to the nearest label embedding by cosine similarity.

```python
label_embeddings = model.encode(["A positive review", "A negative review"])
scores = cosine_similarity(model.encode(texts), label_embeddings)
predictions = scores.argmax(axis=1)
```

Quality depends heavily on how you phrase the labels — "A negative review" works better than
"negative". That sensitivity is a preview of prompt engineering.

### 4. Generative models

Prompt an LLM to classify. Most flexible, most expensive, least consistent.

Where it genuinely wins: nuanced categories that resist definition, labels that change weekly,
reasoning-dependent classification, and cases where you want an explanation alongside the label.

Where it disappoints: cost per call, latency, output format drift, and non-determinism.
**Constrain the output** — enums, structured outputs, or a single-token response — and validate.

The T5 approach shown in the chapter reframes classification as text-to-text ("classify: <text>"),
which is a nice illustration of how the field collapsed every task into one interface.

### Evaluation is unchanged

Alammar uses the same metrics as [G3](../../01-hands-on-ml-geron/notes/ch03.md): precision,
recall, F1, and the confusion matrix. All the same warnings apply — accuracy lies on imbalanced
data, F1 hides the precision/recall decision, and the threshold is a tunable product choice.

One addition specific to LLM classification: **a generative classifier has no threshold to tune.**
You get a label, not a score. That is a real loss of control, and a good reason to prefer
approach 2 when you need to operate at a specific precision.

## Key code

```python
from sentence_transformers import SentenceTransformer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

# Step 1: embed (frozen model, no training)
embedder = SentenceTransformer("sentence-transformers/all-mpnet-base-v2")
X_train = embedder.encode(train_texts, show_progress_bar=True)
X_test = embedder.encode(test_texts)

# Step 2: a linear model on top — trains in seconds, gives you a real threshold
clf = LogisticRegression(max_iter=1000, class_weight="balanced")
clf.fit(X_train, y_train)
print(classification_report(y_test, clf.predict(X_test)))

# And because it's probabilistic, you can pick your operating point
probs = clf.predict_proba(X_test)[:, 1]
```

## Gotchas

- **Starting with a generative model.** Establish the embeddings+logreg baseline first. You need
  a number to beat.
- **Fine-tuning the embedding model prematurely.** Frozen embeddings plus a linear head is
  usually enough. Fine-tune ([A11](ch11.md)) only when it demonstrably is not.
- **Unconstrained LLM output.** "Positive!" vs "positive" vs "The sentiment is positive" — parse
  failures become silent misclassifications. Use structured output.
- **Reporting accuracy on imbalanced labels.** Same trap as
  [G3](../../01-hands-on-ml-geron/notes/ch03.md).
- **Comparing across different embedding models.** Vector spaces are unrelated; you must re-embed
  everything when you switch.
- **Forgetting `class_weight="balanced"`** on skewed data.
- **Expecting a threshold from a generative classifier.** There isn't one, unless you ask for
  logprobs.

## Exercises

**Understand**
1. Name the four approaches and the conditions under which each is correct.
2. Why is embeddings + logistic regression such a strong default?
3. What control do you lose by classifying with a generative model?
4. Why does phrasing the label affect zero-shot embedding classification?

**Build**
1. On a labeled dataset, implement **all four** approaches. Record accuracy, F1, latency per
   example, and cost per 1,000 examples in one table. **This table is the chapter.**
2. Sweep training-set size for approach 2 — 10, 50, 100, 500, 1000 examples — and plot F1. Find
   where the curve flattens; that is how many labels you actually need.
3. Try five phrasings of the same label in zero-shot classification. Quantify the spread.
4. Take the approach-2 classifier and tune the threshold for 95% precision. Report the recall you
   get at that point.

## Flashcards

<!-- card -->
Q: What are the four ways to classify text with modern models?
A: (1) An existing task-specific fine-tuned model; (2) frozen embeddings + a trained classifier; (3) zero-shot via similarity to embedded label descriptions; (4) prompting a generative model. Cost spans about three orders of magnitude.
<!-- /card -->

<!-- card -->
Q: Why should embeddings + logistic regression be your default text classifier?
A: Trains in seconds on CPU from a few hundred examples, deterministic, cheap at inference, versionable, and it gives you a probability — so you get a real precision/recall curve and a tunable threshold. It is also the baseline that tells you whether anything fancier was worth it.
<!-- /card -->

<!-- card -->
Q: What control do you lose when classifying with a generative model?
A: The threshold. You get a label, not a calibrated score, so you cannot dial in a specific precision or recall operating point without asking for logprobs. You also lose determinism and pay far more per call.
<!-- /card -->

<!-- card -->
Q: How does zero-shot classification with embeddings work?
A: Embed descriptions of each label as if they were documents, embed the input, and assign the label with the highest cosine similarity. Quality is sensitive to label phrasing — "A negative review" beats "negative".
<!-- /card -->
