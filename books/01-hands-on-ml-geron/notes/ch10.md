# G10 — Introduction to Artificial Neural Networks with Keras

> **Thesis:** A neural network is a stack of linear transformations separated by nonlinearities,
> trained by the chain rule. Everything else — CNNs, transformers, LLMs — is a choice about what
> the linear layers connect to.

## Why this chapter matters

This is where the second half of the roadmap begins. The MLP you build here has the same
skeleton as the GPT you write in [R4](../../03-build-llm-from-scratch-raschka/notes/ch04.md):
layers, forward pass, loss, backward pass, optimizer step. Get comfortable with that loop now and
Phase 5 is a matter of swapping the layer types.

`[dated]` The Keras API here is TF 2.0-era. Concepts are exactly right; specific calls have moved
(notably `keras.utils` reshuffles and the standalone Keras 3 split). You will write PyTorch from
Phase 5 on, so read for structure.

## Core concepts

### From biological to artificial

The historical framing matters less than one observation: the field's two previous winters ended
not because someone had a better idea, but because **data and compute arrived**. Backprop dates
to 1986. It took until ~2012 for the hardware and datasets to make it work. Keep that in mind
when reading any claim about why a technique "doesn't work."

### The perceptron and its limitation

A **TLU** computes $h_w(x) = \text{step}(w^\top x + b)$. Stack them in a layer and you get a
perceptron. Its famous failure is **XOR** — not linearly separable, so a single layer cannot
represent it.

The fix is depth. An **MLP** — input layer, one or more hidden layers, output layer — solves XOR
easily. But depth is useless with step activations, because the gradient of a step function is
zero everywhere. Which brings us to the actual enabling idea.

### Backpropagation

One phrase to hold: **reverse-mode automatic differentiation plus gradient descent.**

Per mini-batch:
1. **Forward pass** — compute layer by layer, *keeping every intermediate result*.
2. **Compute the loss.**
3. **Backward pass** — apply the chain rule from output to input, computing each parameter's
   contribution to the error.
4. **Gradient descent step** — nudge every weight against its gradient.

Why intermediates are cached is the thing to understand: the chain rule needs the forward
activations. That cache is why training memory is dominated by **activations**, not weights, and
it is exactly the fact that drives Huyen's fine-tuning memory math in
[H7](../../04-ai-engineering-huyen/notes/ch07.md).

**Weight initialization must be random.** Initialize all weights to zero (or any constant) and
every neuron in a layer computes the same thing and receives the same gradient forever — the
layer collapses to a single neuron. Breaking symmetry is the entire job of random init.

### Activation functions

Step functions have zero gradient, so backprop needs something differentiable and nonlinear:

| Function | Range | Notes |
|---|---|---|
| **Sigmoid** σ(z) | (0, 1) | Saturates at both ends → vanishing gradients. Output layer for binary classification. |
| **Tanh** | (−1, 1) | Zero-centered, so it converges faster than sigmoid. Still saturates. |
| **ReLU** max(0,z) | [0, ∞) | Fast, no positive saturation. The default. Can "die". |
| **Softmax** | simplex | Output layer for mutually-exclusive multiclass. |

**Why nonlinearity is required at all:** stack two linear layers and you get another linear layer.
$W_2(W_1x) = (W_2W_1)x$. Depth without nonlinearity buys nothing.

### Architecture choices for an MLP

| Task | Output neurons | Output activation | Loss |
|---|---|---|---|
| Regression | 1 per target | None (or ReLU/softplus if positive) | MSE (MAE/Huber if outliers) |
| Binary classification | 1 | Sigmoid | Binary cross-entropy |
| Multilabel binary | 1 per label | Sigmoid | Binary cross-entropy |
| Multiclass | 1 per class | **Softmax** | Categorical cross-entropy |

That bottom row is the LLM row. A language model is multiclass classification over the vocabulary.

### The three Keras APIs

- **Sequential** — a plain stack. Covers most cases.
- **Functional** — a graph. Needed for multiple inputs/outputs, skip connections
  (**Wide & Deep**), shared layers. Transformers need this class of API.
- **Subclassing** — write `call()` yourself. Maximum flexibility, dynamic control flow, harder to
  save and inspect. This is the style PyTorch uses by default.

### Callbacks and the training loop

`EarlyStopping(restore_best_weights=True)` and `ModelCheckpoint(save_best_only=True)` should be
in essentially every `fit()` you ever write. Early stopping is regularization
([G4](ch04.md)) and it costs nothing.

TensorBoard for visualization — the modern equivalents are Weights & Biases or MLflow.

### Hyperparameter tuning

Géron's practical guidance, still sound:

- **Hidden layers** — start with 1–2, go deeper for complex problems. Depth buys parameter
  efficiency: deep networks reuse low-level structure, which is also why **transfer learning**
  works.
- **Neurons per layer** — the "stretch pants" approach: pick more than you need and rely on early
  stopping and regularization rather than trying to find the perfect width.
- **Learning rate** — *the* most important hyperparameter. Find it by ramping η exponentially
  during a short run and plotting the loss; take the value slightly below where it starts
  climbing. (This is the LR-range test, and it is still standard practice.)
- **Batch size** — large batches use hardware better but can generalize worse. Géron cites the
  warmup trick for making large batches work.
- **Optimizer** — see [ch11](ch11.md).

Prefer **random search** over grid search, for the reason in [G2](ch02.md).

## Key code

```python
import tensorflow as tf
from tensorflow import keras

model = keras.Sequential([
    keras.layers.Flatten(input_shape=[28, 28]),
    keras.layers.Dense(300, activation="relu"),
    keras.layers.Dense(100, activation="relu"),
    keras.layers.Dense(10, activation="softmax"),
])

# sparse_categorical_crossentropy: integer labels
# categorical_crossentropy:        one-hot labels
model.compile(loss="sparse_categorical_crossentropy",
              optimizer=keras.optimizers.SGD(learning_rate=1e-3),
              metrics=["accuracy"])

history = model.fit(X_train, y_train, epochs=30,
                    validation_data=(X_valid, y_valid),
                    callbacks=[keras.callbacks.EarlyStopping(patience=10,
                                                             restore_best_weights=True)])
```

The Functional API, for anything with a non-linear topology:

```python
input_ = keras.layers.Input(shape=X_train.shape[1:])
hidden1 = keras.layers.Dense(30, activation="relu")(input_)
hidden2 = keras.layers.Dense(30, activation="relu")(hidden1)
concat = keras.layers.Concatenate()([input_, hidden2])   # the skip connection
output = keras.layers.Dense(1)(concat)
model = keras.Model(inputs=[input_], outputs=[output])
```

That `Concatenate([input_, hidden2])` is a **skip connection** — the same idea that becomes the
residual stream in a transformer block ([R4](../../03-build-llm-from-scratch-raschka/notes/ch04.md)).

## Gotchas

- **Initializing weights to zero.** Symmetry never breaks; the layer collapses. Always random.
- **Forgetting to scale inputs.** Neural nets are gradient-descent methods — [G4](ch04.md)'s rule
  applies with force.
- **`categorical_crossentropy` with integer labels.** Use `sparse_categorical_crossentropy` for
  integers, `categorical_crossentropy` for one-hot. Mixing them yields a confusing shape error or,
  worse, silently wrong training.
- **Softmax for multilabel.** Softmax forces the outputs to sum to 1 (mutually exclusive). For
  multilabel use independent sigmoids.
- **Not using early stopping.** Free regularization, routinely skipped.
- **Tuning the learning rate last.** Tune it first; it dominates everything else.
- **Stacking Dense layers with no activation.** The composition is still linear. Depth wasted.

## Exercises

**Understand**
1. Why can't a single-layer perceptron solve XOR, and why does adding a layer fix it?
2. Why must activations be nonlinear? What happens if they're not?
3. Why can't weights be initialized to zero?
4. Which activation and loss for: regression, binary, multilabel, multiclass?
5. What does backprop cache during the forward pass, and why does it matter for memory?

**Build**
1. Train a deep MLP on MNIST past 98% accuracy, tuning the learning rate by exponential ramp
   and using early stopping + checkpointing (Géron ex. 10).
2. Implement the learning-rate range test yourself: ramp η from 1e-5 to 10 over one epoch and
   plot loss vs η. Learn to read that curve.
3. Build the Wide & Deep model with the Functional API on housing data, then the same model by
   subclassing. Note which one you can save easily and which you can debug easily.
4. Deliberately remove all activations from a 5-layer MLP and confirm it performs identically to
   linear regression.

## Flashcards

<!-- card -->
Q: What is backpropagation in one sentence?
A: Reverse-mode automatic differentiation combined with gradient descent — a forward pass that caches intermediate activations, then a backward pass applying the chain rule from loss to parameters, then a gradient step.
<!-- /card -->

<!-- card -->
Q: Why can't you initialize all neural network weights to zero?
A: Every neuron in a layer would compute the same output and receive the same gradient, so they would stay identical forever — the layer collapses to a single neuron. Random initialization breaks the symmetry.
<!-- /card -->

<!-- card -->
Q: Why must activation functions be nonlinear?
A: Composing linear layers gives another linear layer: W₂(W₁x) = (W₂W₁)x. Without nonlinearity, any depth of network is equivalent to a single linear layer.
<!-- /card -->

<!-- card -->
Q: Which output activation and loss for multiclass classification, and why does it matter for LLMs?
A: Softmax output with categorical cross-entropy. This is exactly an LLM's output layer — next-token prediction is multiclass classification over the vocabulary.
<!-- /card -->

<!-- card -->
Q: `sparse_categorical_crossentropy` vs `categorical_crossentropy`?
A: Sparse takes integer class indices; the non-sparse version takes one-hot vectors. Using the wrong one gives a shape error or silently wrong training.
<!-- /card -->

<!-- card -->
Q: How do you find a good learning rate?
A: The LR-range test: ramp the learning rate exponentially during a short training run and plot the loss against it. Choose a value slightly below where the loss starts to climb.
<!-- /card -->

<!-- card -->
Q: Why does training memory scale with activations rather than weights?
A: Backprop needs the forward-pass activations to apply the chain rule, so they are all cached until the backward pass consumes them. This is the basis of fine-tuning memory math and of gradient-checkpointing as a mitigation.
<!-- /card -->
