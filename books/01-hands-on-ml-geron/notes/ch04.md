# G4 — Training Models

> **Thesis:** Almost all of machine learning is gradient descent on a regularized loss. Once you
> see that, every model in the rest of the book — and every LLM in the rest of this roadmap — is
> a variation on one idea.

## Why this chapter matters

This is where the black box opens. Chapters 1–3 treated models as things with `.fit()`. This one
shows you the machinery, and that machinery is *the same machinery* Raschka uses to pretrain a
GPT in Phase 5. Learning rate, batch size, convergence, regularization — the vocabulary you get
here is the vocabulary you will use for the next 26 weeks.

## Core concepts

### Two ways to fit a linear model

**Closed form — the Normal Equation:**

$$\hat{\theta} = (X^\top X)^{-1} X^\top y$$

Exact, no hyperparameters, one shot. Scikit-learn actually uses the **pseudoinverse** via SVD,
which is more numerically stable and works even when $X^\top X$ is singular.

Complexity: about $O(n^{2.4})$ to $O(n^3)$ in the number of **features**. Double the features and
it gets ~5–8× slower. Linear in the number of *instances*, so it handles many rows fine.

**Iterative — Gradient Descent.** Start anywhere, repeatedly step downhill:

$$\theta \leftarrow \theta - \eta \nabla_\theta \text{MSE}(\theta)$$

Scales to many features and, in its stochastic form, to datasets that do not fit in memory. This
is the one that generalizes to neural networks.

### Feature scaling is not optional for GD

When features have wildly different scales, the cost function's contours become elongated
ellipses. Gradient descent then zig-zags down a narrow valley and takes far longer to converge.
Scale your features and the bowl becomes round and the path becomes direct.

The Normal Equation does not care. Gradient descent cares enormously. Since everything from
chapter 10 onward is gradient descent, **always scale**.

### The three flavours

| | Uses per step | Converges | Escapes local minima | Supports out-of-core |
|---|---|---|---|---|
| **Batch GD** | All *m* instances | Smoothly to the minimum | No | No |
| **Stochastic GD** | 1 instance | Bounces near the minimum | Yes | Yes |
| **Mini-batch GD** | A small batch | Mostly smooth, some bounce | Somewhat | Yes |

**Batch** is slow on large datasets but its path is stable. **Stochastic** is fast and noisy —
the noise helps it jump out of local minima but stops it from ever settling exactly, which is
what a **learning schedule** (decaying η) fixes. **Mini-batch** is the practical compromise and
gets a hardware bonus: batched matrix operations use GPUs efficiently.

> **Look ahead:** every LLM you will ever train uses mini-batch GD with a decaying schedule.
> Raschka's chapter 5 training loop is this table's third row. Appendix D adds warmup and cosine
> decay — refinements of the same schedule idea.

### Polynomial regression and the learning-curve diagnostic

Add powers of your features and a linear model can fit curves — `PolynomialFeatures(degree=d)`
also adds cross terms, so the feature count explodes combinatorially. Degree 3 on 100 features
gives ~176,000 features.

**Learning curves** — train and validation error as a function of training-set size — are how you
tell overfitting from underfitting without guessing:

| Pattern | Diagnosis | Fix |
|---|---|---|
| Both curves plateau **high**, close together | **Underfitting** | More complex model, better features |
| Training error low, **large gap** to validation | **Overfitting** | More data, regularization, simpler model |

The key asymmetry: **adding more data helps overfitting and does nothing for underfitting.** If
both curves have plateaued together, more data is wasted money.

### The bias/variance decomposition

Generalization error = **bias** + **variance** + **irreducible error**.

- **Bias** — wrong assumptions (assuming linear when it's quadratic). High bias → underfit.
- **Variance** — excessive sensitivity to the particular training sample. High variance → overfit.
- **Irreducible error** — noise in the data. Only fixable by fixing the data.

Increasing complexity raises variance and lowers bias. This tradeoff never goes away; it just
gets renamed. (In LLM work it shows up as "should I fine-tune on my 500 examples?" — usually a
variance question.)

### Three regularized linear models

Constrain the weights and you constrain overfitting.

**Ridge (ℓ₂):** adds $\alpha \sum \theta_i^2$. Shrinks weights toward zero, never *to* zero.

**Lasso (ℓ₁):** adds $\alpha \sum |\theta_i|$. Drives some weights **exactly to zero** — it
performs automatic feature selection. The reason is geometric: the ℓ₁ constraint region is a
diamond with corners on the axes, and corners are where optima land.

**Elastic Net:** a mix, controlled by `l1_ratio`. Géron's guidance:

> Ridge by default. Lasso or Elastic Net if you suspect few features matter. **Prefer Elastic Net
> to Lasso** when features outnumber instances or several features are strongly correlated —
> plain Lasso behaves erratically there.

Critically: **regularize the bias term? No.** The intercept is not penalized. And **always scale
before regularizing** — otherwise the penalty punishes features for their units.

**Early stopping** is regularization too, and the cheapest kind: stop when validation error stops
improving. With SGD, keep a snapshot of the best model, because the noisy path may wander away
from the optimum before you notice.

### Logistic and softmax regression

**Logistic regression** puts a sigmoid on a linear model: $\hat{p} = \sigma(\theta^\top x)$ where
$\sigma(t) = 1/(1+e^{-t})$.

Its cost is **log loss** (cross-entropy):

$$J(\theta) = -\tfrac{1}{m}\sum \left[ y^{(i)}\log(\hat{p}^{(i)}) + (1-y^{(i)})\log(1-\hat{p}^{(i)}) \right]$$

There is no closed form, but the function is **convex**, so gradient descent finds the global
optimum. Note the shape of the penalty: $-\log(\hat p)$ explodes as $\hat p \to 0$. **Being
confidently wrong is punished enormously.** That single property is why models learn calibration
at all — and it is exactly the loss Raschka uses in chapter 5, just applied over a 50,257-token
vocabulary instead of two classes.

**Softmax regression** generalizes it to *K* mutually exclusive classes:

$$\hat{p}_k = \frac{\exp(s_k(x))}{\sum_{j=1}^{K}\exp(s_j(x))}$$

with cross-entropy as the cost. Multiclass, not multi-output — softmax cannot say "cat and dog."

> **This is the single most important formula in the roadmap.** An LLM's final layer is a softmax
> over the vocabulary; next-token prediction is softmax regression with *K* ≈ 50,000, and
> **temperature** is a scalar dividing the logits $s_k$ before that exponential. Everything in
> [R5](../../03-build-llm-from-scratch-raschka/notes/ch05.md) and
> [H2](../../04-ai-engineering-huyen/notes/ch02.md) about sampling is this equation.

## Key code

```python
from sklearn.linear_model import SGDRegressor, Ridge, Lasso, ElasticNet, LogisticRegression

# `penalty="l2"` + a learning schedule ~= Ridge trained by SGD
sgd = SGDRegressor(max_iter=1000, tol=1e-3, penalty="l2", alpha=0.1,
                   eta0=0.1, learning_rate="invscaling")

# Early stopping done manually, keeping the best snapshot
best_val, best_model = float("inf"), None
sgd = SGDRegressor(max_iter=1, warm_start=True, learning_rate="constant", eta0=5e-4)
for epoch in range(1000):
    sgd.fit(X_train, y_train)             # warm_start continues where it left off
    val_err = mean_squared_error(y_val, sgd.predict(X_val))
    if val_err < best_val:
        best_val, best_model = val_err, deepcopy(sgd)
```

## Gotchas

- **Not scaling before gradient descent or regularization.** Slow convergence, and a penalty
  that punishes features for their measurement units.
- **A learning rate that is too high.** The loss diverges — it increases, often to `nan`. Too
  low and it converges truthfully but takes forever. Plot the loss; you will see which.
- **Assuming SGD converges.** It bounces around the optimum forever unless you decay η.
- **Regularizing the intercept.** Don't.
- **Using Lasso with correlated features.** It picks one arbitrarily and zeroes the rest. Use
  Elastic Net.
- **Polynomial feature explosion.** `degree=3` on 100 features → ~176k features → out of memory.
- **Thinking softmax handles multi-label.** It is mutually exclusive by construction. For
  multi-label, use *K* independent sigmoids.

## Exercises

**Understand**
1. You have 100,000 features. Normal Equation or SGD, and why?
2. Your features have very different scales. Which algorithms suffer, and which don't?
3. Can gradient descent get stuck in a local minimum on logistic regression's cost? Why not?
4. Training error and validation error are both high and equal. Is more data going to help?
5. Validation error is much higher than training error. Name three fixes.
6. Why does ℓ₁ zero out weights while ℓ₂ merely shrinks them?

**Build**
1. Implement batch gradient descent for softmax regression with early stopping — **no
   scikit-learn** (Géron's exercise 12). This is the single most valuable exercise in the first
   nine chapters; you are writing a training loop by hand.
2. Plot learning curves for polynomial degrees 1, 2, 10 on the same data. Identify each regime.
3. Sweep the learning rate over `[1e-4, 1e-3, 1e-2, 1e-1, 1]` and plot the loss curves together.
   Recognize the shapes — you will see them again in every training run for the rest of your life.
4. Compare Ridge, Lasso, and Elastic Net on data with deliberately correlated features. Inspect
   which coefficients get zeroed.

## Flashcards

<!-- card -->
Q: Why must you scale features before gradient descent?
A: Unscaled features make the cost surface an elongated valley, so GD zig-zags and converges slowly. Scaled features make it a round bowl with a direct path. (The Normal Equation is unaffected.)
<!-- /card -->

<!-- card -->
Q: Batch vs stochastic vs mini-batch GD?
A: Batch uses all instances per step — stable but slow, no out-of-core. Stochastic uses one — fast, noisy, escapes local minima, never settles without a decaying schedule. Mini-batch uses a small batch — the practical compromise, and it exploits GPU matrix ops.
<!-- /card -->

<!-- card -->
Q: How do learning curves distinguish underfitting from overfitting?
A: Both curves plateauing high and close together = underfitting (more data won't help). Low training error with a large gap to validation = overfitting (more data will help).
<!-- /card -->

<!-- card -->
Q: Why does ℓ₁ (Lasso) produce exactly-zero weights while ℓ₂ (Ridge) does not?
A: The ℓ₁ constraint region is a diamond whose corners lie on the axes, and optima tend to land on corners — a corner means some coordinate is exactly 0. ℓ₂'s region is a sphere with no corners, so it shrinks smoothly toward zero without reaching it.
<!-- /card -->

<!-- card -->
Q: Write the softmax function and say why it matters for LLMs.
A: p_k = exp(s_k) / Σ_j exp(s_j). An LLM's output layer is a softmax over the vocabulary — next-token prediction *is* softmax regression with K ≈ 50,000 classes, and temperature is a scalar dividing s_k before exponentiating.
<!-- /card -->

<!-- card -->
Q: Why does log loss punish confident wrong answers so severely?
A: The cost includes −log(p̂) for the true class, which goes to infinity as p̂ → 0. Predicting 0.001 for something that happens costs ~6.9; predicting 0.5 costs ~0.69.
<!-- /card -->

<!-- card -->
Q: Ridge, Lasso, or Elastic Net?
A: Ridge by default. Lasso when you believe only a few features matter (it selects them). Elastic Net over plain Lasso when features outnumber instances or several are strongly correlated, because Lasso behaves erratically there.
<!-- /card -->
