# G6 — Decision Trees

> **Thesis:** A decision tree is a nested sequence of yes/no questions greedily chosen to purify
> the data — powerful, completely interpretable, and so high-variance that its main use is as an
> ingredient in something else.

## Why this chapter matters

Two reasons. First, trees are **white-box models**: you can print the exact reasoning for any
prediction, which nothing in the LLM half of this roadmap can offer. Second, they are the
building block for chapter 7's ensembles, and gradient-boosted trees remain the best tool for
tabular data — including, quite often, the classifier you will put in front of an LLM as a router
or a guardrail.

## Core concepts

### How CART builds a tree

Scikit-learn uses **CART**, which produces only binary trees. At each node it searches for the
single (feature *k*, threshold *t*) pair that minimizes:

$$J(k, t) = \frac{m_{\text{left}}}{m} G_{\text{left}} + \frac{m_{\text{right}}}{m} G_{\text{right}}$$

— the impurity of the two children, weighted by their size. Then it recurses. It never revisits
an earlier split.

**CART is greedy.** It takes the best split available *now*, not the sequence of splits that
would be best overall. Finding the optimal tree is NP-complete, so greedy-and-good-enough is the
deal. Consequence: your tree is a decent solution, not the solution.

### Gini vs entropy

**Gini impurity:** $G_i = 1 - \sum_k p_{i,k}^2$ — probability of mislabeling a random instance
if you labeled it by the node's class distribution. Zero when pure.

**Entropy:** $H_i = -\sum_{p_{i,k} \neq 0} p_{i,k}\log_2(p_{i,k})$ — the information-theoretic
measure.

They mostly agree. Gini is slightly faster (no log) and is the default. Entropy tends to produce
slightly more balanced trees. **This is not a decision worth agonizing over.**

> Worth noticing: entropy here is the same quantity Huyen uses to explain
> **perplexity** in [H3](../../04-ai-engineering-huyen/notes/ch03.md). Impurity of a node and
> uncertainty of a language model are the same measure of "how surprised am I."

### Regularization: trees have no built-in limit

Left alone, a tree splits until every leaf is pure — memorizing the training set exactly. It is a
**nonparametric model**: the parameter count is not fixed before training, so nothing constrains
it. This is why chapter 2's tree scored RMSE 0 on training data.

The knobs, all of which restrict growth:

| Hyperparameter | Effect | Direction to reduce overfitting |
|---|---|---|
| `max_depth` | Tree height | ↓ |
| `min_samples_split` | Min samples to split a node | ↑ |
| `min_samples_leaf` | Min samples in a leaf | ↑ |
| `min_weight_fraction_leaf` | Same, as a fraction | ↑ |
| `max_leaf_nodes` | Total leaves | ↓ |
| `max_features` | Features considered per split | ↓ |

Mnemonic: **increasing `min_*` and decreasing `max_*` regularizes.**

### Predictions and probabilities

A leaf's class probabilities are just the training class ratios in that leaf. So **every instance
landing in the same leaf gets the identical probability estimate**, no matter where it sits in
that region. Tree probabilities are coarse; do not treat them as calibrated.

### Complexity

Training: $O(n \times m \log_2 m)$. Prediction: $O(\log_2 m)$ — traverse one path, independent of
feature count. Prediction is extremely fast, which is why trees show up in latency-sensitive
places.

### The two real weaknesses

**1. Orthogonal boundaries.** Every split is axis-aligned, so a diagonal boundary becomes a
staircase. Rotate the dataset 45° and a perfectly simple problem produces a convoluted tree that
generalizes badly. **PCA (chapter 8) often helps** by rotating the data to better-aligned axes.

**2. Variance.** Tiny changes to the training data produce a completely different tree. Even
retraining on the *same* data gives a different result, because scikit-learn samples features
randomly at each split (set `random_state` for reproducibility).

Weakness 2 is not really fixed — it is *exploited*. Averaging many high-variance, low-bias models
cancels the variance. That is chapter 7, and it is why decision trees matter more as an
ingredient than as a model.

## Key code

```python
from sklearn.tree import DecisionTreeClassifier, export_graphviz

# An unregularized tree WILL memorize the training set. Always constrain it.
tree = DecisionTreeClassifier(max_depth=3, min_samples_leaf=10, random_state=42)
tree.fit(X, y)

# White-box: export and actually look at it
export_graphviz(tree, out_file="tree.dot", feature_names=names,
                class_names=classes, rounded=True, filled=True)
```

## Gotchas

- **Leaving the tree unconstrained.** It will reach 100% training accuracy and generalize badly.
- **Reading leaf probabilities as calibrated.** They are training frequencies in a coarse region.
- **Expecting stability.** Retraining changes the tree; slight data changes change it a lot.
  Never present a single tree's structure as "the explanation" of a phenomenon.
- **Scaling features.** Unnecessary — splits are per-feature thresholds. Harmless but pointless.
- **Trusting `feature_importances_` with correlated features.** Importance gets split
  arbitrarily between correlated columns. Use permutation importance if it matters.
- **Diagonal boundaries.** If your problem is inherently rotational, trees will struggle. Try PCA.

## Exercises

**Understand**
1. Roughly what depth does an unconstrained tree reach on 1M instances?
2. Is a node's Gini impurity generally lower or higher than its parent's? Always, or on average?
3. Your tree overfits. Which hyperparameters do you move and in which direction?
4. Should you scale features for a decision tree? Why or why not?

**Build**
1. Train and fine-tune a tree on `make_moons` with 10k instances; grid search `max_leaf_nodes`.
   Expect ~85–87% (Géron ex. 7).
2. **Grow a forest by hand** (ex. 8): 1,000 subsets of 100 instances each, one tree per subset,
   then majority-vote across trees. Accuracy should rise ~1.5%. You have just built a random
   forest — do this *before* chapter 7 and the whole ensemble idea will land properly.
3. Rotate a 2D dataset 45°, train a tree on both versions, and plot the boundaries. See the
   staircase.

## Flashcards

<!-- card -->
Q: What does the CART algorithm optimize at each node?
A: It greedily searches for the (feature, threshold) pair minimizing the size-weighted impurity of the two resulting children, then recurses. It never revisits a split — finding the globally optimal tree is NP-complete.
<!-- /card -->

<!-- card -->
Q: Gini impurity vs entropy — which should you use?
A: Rarely matters. Gini is slightly faster (no logarithm) and is the default; entropy tends to yield slightly more balanced trees. Not a decision worth agonizing over.
<!-- /card -->

<!-- card -->
Q: Which hyperparameters regularize a decision tree, and in which direction?
A: Increase the `min_*` parameters (`min_samples_split`, `min_samples_leaf`) and decrease the `max_*` ones (`max_depth`, `max_leaf_nodes`, `max_features`).
<!-- /card -->

<!-- card -->
Q: Why are decision trees called high-variance models?
A: Small changes in the training data produce a completely different tree structure. Ensembling (bagging, random forests) exploits exactly this: averaging many high-variance, low-bias models cancels the variance.
<!-- /card -->

<!-- card -->
Q: What is the orthogonal-boundary limitation?
A: Every CART split is axis-aligned, so a diagonal decision boundary must be approximated by a staircase. Rotating the data can turn a trivial problem into a convoluted tree; PCA sometimes fixes it.
<!-- /card -->
