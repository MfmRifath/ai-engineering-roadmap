# G16 — Natural Language Processing with RNNs and Attention

> **Thesis:** Compressing an entire sentence into one fixed vector is the bottleneck; attention
> removes it by letting the decoder look back at every input position and decide, per step, what
> matters.

## Why this chapter matters

**This is the bridge.** Everything before it is preparation; everything after it in this roadmap
is consequence. Géron ends the chapter roughly where the modern era begins — GPT-1 and BERT are
the last thing he covers — which makes it the ideal setup for
[Alammar](../../02-hands-on-llms-alammar/) and
[Raschka](../../03-build-llm-from-scratch-raschka/).

Read it for one purpose: **feel the problem before you are shown the solution.** Encoder–decoder
translation with a single context vector, watch it fail on long sentences, then see attention
fix it. If you skip to the transformer diagram without that setup, attention will look like an
arbitrary formula instead of an obvious fix.

## Core concepts

### Character-RNN, and the sampling ideas that persist

Train on text, predict the next character, sample repeatedly. Two mechanisms defined here that
you will use for the rest of the roadmap:

- **Temperature.** Divide the logits by *T* before softmax. Low *T* → the distribution sharpens
  toward the argmax (conservative, repetitive). High *T* → flattens toward uniform (diverse,
  incoherent). This is the same knob you set on every LLM API call, doing the same arithmetic.
- **Stateful RNNs.** Preserve the hidden state across batches to model longer context. Requires
  sequential, non-overlapping, non-shuffled batches — a real constraint that shows how awkward
  long context was before attention.

### The seq2seq bottleneck

Encoder–decoder translation: the encoder reads the source sentence and produces a **single fixed
vector**; the decoder generates the target from it.

The failure is intuitive once stated. Every word of a 50-word sentence must be squeezed into one
vector of a few hundred numbers, and by the time the encoder reaches the end, the beginning has
been overwritten many times. **Translation quality degrades sharply with sentence length.**

Bahdanau's 2014 question is the pivot of the whole field: *why should the decoder be limited to
one vector? Why not let it look at all the encoder's outputs, and learn which ones matter at each
step?*

### Attention

Instead of one context vector, the decoder computes a **new, weighted context vector at every
output step**:

$$\alpha_{(t,i)} = \frac{\exp(e_{(t,i)})}{\sum_{i'} \exp(e_{(t,i')})}, \qquad
c_{(t)} = \sum_i \alpha_{(t,i)} \, h_{(i)}$$

In words: score how relevant each encoder output $h_{(i)}$ is to the current decoder state,
softmax the scores into weights that sum to 1, and take the weighted average. **Attention is a
soft, differentiable lookup** — a weighted average where the model learns the weights.

Two scoring functions:
- **Bahdanau (additive/concatenative)** — a small neural network scores each pair.
- **Luong (multiplicative)** — a dot product, optionally with a learned matrix. Simpler and
  faster; scaled dot-product is what transformers use.

The alignment weights $\alpha$ are **interpretable**: plotting them shows which source words the
model looked at for each output word, and for translation they recover word alignment without
ever being taught it. This is the ancestor of every attention-map visualization you have seen.

### "Attention Is All You Need"

Vaswani et al., 2017 — the paper that removed recurrence and convolution entirely.

**Scaled dot-product attention:**

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

The QKV framing is a database analogy worth internalizing:
- **Query** — what this position is looking for
- **Key** — what each position offers
- **Value** — what each position actually contributes if selected

Why divide by $\sqrt{d_k}$: for large $d_k$, dot products of random vectors grow with dimension,
pushing the softmax into a saturated regime where one weight is ~1 and gradients vanish. The scale
factor keeps the variance ~1. Géron notes this explicitly and it is a favourite interview
question.

**Multi-head attention.** Project Q, K, V into *h* lower-dimensional subspaces, attend in each
independently, concatenate. Different heads specialize — one tracks syntactic agreement, another
coreference. One attention operation can only produce one weighted average; multiple heads let
the model attend to several things at once.

**Positional encodings.** Attention is *permutation-invariant* — it sees a set, not a sequence.
Word order must be injected explicitly. The original paper uses fixed sinusoids of varying
frequency, which lets the model attend to relative positions and extrapolate beyond training
lengths. `[dated]` Modern models use **RoPE** (rotary embeddings) or learned positional
embeddings; the *need* is unchanged.

**Masked attention** in the decoder prevents attending to future positions. Everything Géron
describes here as a decoder is what you will build as a causal GPT block in
[R3](../../03-build-llm-from-scratch-raschka/notes/ch03.md).

### The pretraining turn

The chapter ends with ELMo, ULMFiT, GPT-1, and BERT — the insight that you can pretrain on
enormous unlabeled corpora with a self-supervised objective, then fine-tune on a small labeled
task set.

`[dated]` And that is the doorstep of everything after. Géron could not know that scaling this
recipe was the whole story. **This is exactly where [Alammar ch. 1](../../02-hands-on-llms-alammar/notes/ch01.md)
picks up.**

## Key code

```python
# Temperature sampling — the same arithmetic as every LLM API's temperature param
def next_char(text, temperature=1.0):
    y_proba = model.predict(preprocess([text]))[0, -1:, :]
    rescaled_logits = tf.math.log(y_proba) / temperature
    char_id = tf.random.categorical(rescaled_logits, num_samples=1) + 1
    return tokenizer.sequences_to_texts(char_id.numpy())[0]
```

Scaled dot-product attention, stripped to its essentials — nine lines, and it replaced an entire
architecture family:

```python
import torch, math

def attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)   # sqrt(d_k): keep softmax out of saturation
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    weights = torch.softmax(scores, dim=-1)              # rows sum to 1
    return weights @ V, weights
```

You will write the full version in
[`src/aieng/transformer/attention.py`](../../../src/aieng/transformer/attention.py).

## Gotchas

- **Forgetting the $\sqrt{d_k}$ scaling.** Large dot products saturate the softmax and gradients
  vanish. The model trains badly in a way that is hard to attribute.
- **Forgetting positional encoding.** Attention is permutation-invariant; without positions the
  model literally cannot tell "dog bites man" from "man bites dog."
- **Confusing self-attention with cross-attention.** Self: Q, K, V all come from the same
  sequence. Cross: Q from the decoder, K and V from the encoder.
- **Applying temperature to probabilities instead of logits.** Temperature divides the **logits**
  before softmax.
- **Reading attention weights as explanations.** They show where the model looked, not why it
  decided. A large and contested literature says attention is not explanation.
- **Stateful RNN batching.** Requires sequential, non-shuffled, non-overlapping windows and a
  state reset each epoch. Easy to get subtly wrong.

## Flashcards

<!-- card -->
Q: What problem does attention solve in seq2seq models?
A: The fixed-size context-vector bottleneck. Rather than compressing the whole input into one vector, the decoder computes a fresh weighted combination of *all* encoder outputs at every output step, so translation quality no longer collapses on long sentences.
<!-- /card -->

<!-- card -->
Q: Write scaled dot-product attention and name each term.
A: Attention(Q,K,V) = softmax(QKᵀ/√d_k)V. Query = what this position seeks; Key = what each position offers; Value = what each contributes when selected. The softmax turns scores into weights summing to 1; the result is a weighted average of values.
<!-- /card -->

<!-- card -->
Q: Why divide by √d_k in attention?
A: For large d_k, dot products of random vectors have variance proportional to d_k, so the scores get large and push the softmax into saturation, where one weight is ~1 and gradients vanish. Dividing by √d_k restores variance ~1.
<!-- /card -->

<!-- card -->
Q: Why is multi-head attention better than a single attention operation?
A: One attention op produces exactly one weighted average, so it can attend to only one thing. Multiple heads attend in different learned subspaces simultaneously — one may track syntactic agreement while another tracks coreference.
<!-- /card -->

<!-- card -->
Q: Why do transformers need positional encodings?
A: Self-attention is permutation-invariant — it treats the input as a set. Without explicit position information the model cannot distinguish "dog bites man" from "man bites dog."
<!-- /card -->

<!-- card -->
Q: What does temperature do, mechanically?
A: Divides the logits by T before the softmax. T < 1 sharpens the distribution toward the argmax (conservative); T > 1 flattens it toward uniform (diverse). It is applied to logits, not to probabilities.
<!-- /card -->

<!-- card -->
Q: Self-attention vs cross-attention?
A: In self-attention, Q, K, and V all come from the same sequence. In cross-attention, Q comes from the decoder while K and V come from the encoder — which is how a decoder consults the source sentence.
<!-- /card -->
