# G3 — Classification

> **Thesis:** Accuracy is almost always the wrong metric, and the right one depends on which
> mistake costs you more.

## Why this chapter matters

This is the most transferable chapter in the book. Precision, recall, and the threshold that
trades between them reappear verbatim in retrieval quality
([H6](../../04-ai-engineering-huyen/notes/ch06.md)), in guardrail tuning, and in every
classifier you will ever put in front of an LLM. Engineers who never internalized this chapter
spend their careers reporting one number and being surprised by production.

## Core concepts

### Why accuracy lies

Géron's demonstration is the best one in print. On MNIST, build a "5-detector" that **always
predicts not-5**:

```python
class Never5Classifier(BaseEstimator):
    def predict(self, X):
        return np.zeros((len(X), 1), dtype=bool)
```

It scores **90% accuracy**. Because only ~10% of digits are 5s. It has learned nothing.

**Accuracy is unusable on imbalanced data**, and almost all interesting data is imbalanced:
fraud, disease, spam, defects, safety violations.

### The confusion matrix

Everything else is derived from these four cells:

|  | Predicted Negative | Predicted Positive |
|---|---|---|
| **Actually Negative** | TN | **FP** (false alarm, Type I) |
| **Actually Positive** | **FN** (miss, Type II) | TP |

### Precision and recall

$$\text{precision} = \frac{TP}{TP + FP} \qquad \text{recall} = \frac{TP}{TP + FN}$$

In words:
- **Precision** — of the things I flagged, how many were right? *Cost of a false alarm.*
- **Recall** (sensitivity, TPR) — of the things I should have flagged, how many did I catch?
  *Cost of a miss.*

Which one you want is a **product decision, not a statistical one**:

| Task | Optimize | Because a mistake means |
|---|---|---|
| Video safe-for-kids filter | **Precision** | One bad video shown is a scandal; a missed good video is invisible |
| Shoplifter detection from CCTV | **Recall** | A missed thief is a loss; a false alarm is a guard's 30 seconds |
| Cancer screening | **Recall** | A miss can be fatal; a false positive means one more test |
| Automated bulk email deletion | **Precision** | Deleting a real email is unrecoverable |

**F₁** is their harmonic mean — high only when *both* are high:

$$F_1 = \frac{2}{\frac{1}{\text{precision}} + \frac{1}{\text{recall}}}$$

Use F₁ when you genuinely have no preference. That is rarer than people pretend. Reporting F₁
because you did not want to make the decision is a way of hiding it.

### The precision/recall tradeoff is a threshold

The key mechanical insight. A classifier computes a **score**; the label comes from comparing it
to a threshold. Raise the threshold → fewer positives → precision up, recall down. There is no
setting where both improve, which is why "improve precision and recall" is not a coherent
instruction.

```python
y_scores = cross_val_predict(sgd_clf, X_train, y_train_5, cv=3,
                             method="decision_function")
precisions, recalls, thresholds = precision_recall_curve(y_train_5, y_scores)

# pick the lowest threshold that achieves >= 90% precision
threshold_90 = thresholds[np.argmax(precisions >= 0.90)]
y_pred_90 = (y_scores >= threshold_90)
```

Note `method="decision_function"` — you need raw scores, not labels, to sweep the threshold.
Some classifiers expose `predict_proba` instead; `RandomForestClassifier` is one.

The precision curve is **bumpy** as the threshold rises, while recall is smooth. That is not a
bug: adding one more prediction can lower precision locally.

### PR curve vs ROC curve — and when each lies

The **ROC curve** plots TPR (recall) against FPR. **AUC** summarizes it; a perfect classifier is
1.0, random is 0.5.

Géron's rule is the thing to keep:

> Prefer the **PR curve** when the positive class is rare, or when you care more about false
> positives than false negatives. Otherwise use ROC.

**Why:** FPR = FP/(FP+TN). When negatives massively outnumber positives, TN is enormous, so FP
has to grow absurdly before FPR moves. ROC AUC therefore looks great on imbalanced problems even
when the classifier is useless in practice. The PR curve has no TN term anywhere, so it cannot
be flattered this way.

The chapter's SGD vs RandomForest comparison shows exactly this: both look fine on ROC; the PR
curve separates them clearly.

### Multiclass strategies

Binary classifiers get extended two ways:

- **OvR / OvA** (one-vs-rest) — *N* classifiers, each "is it class k?", take the highest score.
  *N* classifiers total. The default for most algorithms.
- **OvO** (one-vs-one) — one classifier per pair, *N(N−1)/2* of them, vote. Each trains on only
  two classes' data, so it is preferred when training scales badly with dataset size — notably
  **SVMs**.

Scikit-learn picks automatically; force it with `OneVsRestClassifier` / `OneVsOneClassifier`.

**Error analysis** via a normalized confusion matrix is the highest-value debugging move in the
chapter: plot it as an image, zero the diagonal, and look at what is bright. On MNIST, 3↔5 and
4↔9 dominate — which suggests a preprocessing fix (image centering/rotation) rather than a model
change.

### Multilabel and multioutput

- **Multilabel** — several binary labels per instance ("is large", "is odd"). Score with
  `f1_score(..., average="macro")` for equal class weight, `"weighted"` to weight by support.
- **Multioutput** — each label is itself multiclass. Géron's denoising example outputs 784
  pixel intensities, blurring the line between classification and regression.

## Key code

```python
from sklearn.metrics import (confusion_matrix, precision_score, recall_score,
                             f1_score, precision_recall_curve, roc_auc_score)
from sklearn.model_selection import cross_val_predict

# Never evaluate on the training set — cross_val_predict gives you clean
# out-of-fold predictions for every training instance.
y_pred = cross_val_predict(clf, X_train, y_train, cv=3)
print(confusion_matrix(y_train, y_pred))

# Error analysis: normalize by row, zero the diagonal, look at what's bright.
cm = confusion_matrix(y_train, y_pred)
norm = cm / cm.sum(axis=1, keepdims=True)
np.fill_diagonal(norm, 0)
plt.matshow(norm, cmap=plt.cm.gray)
```

## Gotchas

- **Reporting accuracy on imbalanced data.** 90% can mean "predicts the majority class always."
- **Reporting ROC AUC on rare positives.** The huge TN count suppresses FPR and flatters you.
  Use PR AUC.
- **Tuning the threshold on the test set.** The threshold is a hyperparameter. Pick it on
  validation.
- **Calling `precision_recall_curve` with labels instead of scores.** You need
  `decision_function` or `predict_proba`, otherwise you get a two-point curve.
- **`predict_proba` is not calibrated.** A random forest's 0.9 does not mean 90% likely. If you
  need real probabilities, use `CalibratedClassifierCV`.
- **Averaging F₁ without thinking.** `macro` treats rare classes as equally important; `weighted`
  lets the majority class dominate. Different claims about what matters.
- **Reporting F₁ to dodge the precision/recall decision.** Make the decision.

2. Give one task where 99% recall at 10% precision is the correct operating point.
3. Why can ROC AUC look excellent on a useless rare-event classifier?
4. Why is the precision-vs-threshold curve bumpy while recall's is monotonic?

**Build**

   (Géron's exercise 1).

   *preprocessing* fix rather than a model change.

## Flashcards

<!-- card -->
Q: Why is accuracy a bad metric for imbalanced classification?
A: A classifier that always predicts the majority class gets high accuracy while learning nothing. On MNIST's 5-detector, "always not-5" scores 90%.
<!-- /card -->

<!-- card -->
Q: Precision vs recall, in one line each.
A: Precision = of what I flagged, how much was correct (TP/(TP+FP)) — the cost of false alarms. Recall = of what I should have flagged, how much I caught (TP/(TP+FN)) — the cost of misses.
<!-- /card -->

<!-- card -->
Q: When should you prefer a PR curve over a ROC curve?
A: When the positive class is rare, or when false positives matter more than false negatives. FPR's denominator includes the huge TN count, so ROC AUC stays optimistic on imbalanced data; PR has no TN term.
<!-- /card -->

<!-- card -->
Q: How do you actually trade precision for recall?
A: Move the decision threshold on the classifier's score. Higher threshold → fewer positives → higher precision, lower recall. Get scores with `decision_function` or `predict_proba`, then sweep.
<!-- /card -->

<!-- card -->
Q: OvR vs OvO for multiclass — when is OvO preferred?
A: OvR trains N classifiers on the full dataset. OvO trains N(N−1)/2 classifiers, each on only two classes' data. Prefer OvO when the algorithm scales badly with dataset size — notably SVMs.
<!-- /card -->

<!-- card -->
Q: What is F₁ and when is it the wrong choice?
A: The harmonic mean of precision and recall, high only when both are. It is wrong whenever you genuinely care more about one error type than the other — which is most of the time. Reaching for F₁ can be a way of avoiding a product decision.
<!-- /card -->
